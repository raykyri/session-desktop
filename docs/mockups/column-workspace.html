Summary

The proposal turns the research view into one horizontal strip of columns: the feed, then the open conversation as a pair of columns, then each open branch as another pair to its right. Questions in the feed can be filed into Drafts, Archive, and user folders by dragging. A conversation is a messages column (the user's messages, with the ask box at the end) next to an answer column that shows the answer to the selected message. A branch opens as the next pair, from a passage in the answer or from a marker in the answer's right margin.

Every level, root or branch, is the same pair, so going deeper adds columns and never changes the width of the ones already open; the strip scrolls sideways when they don't fit. Rows are quiet: no fill or separators at rest, an inset rounded bubble on hover and selection, and a faint accent ring on the row that has keyboard focus. The left sidebar can collapse to a 52px icon strip, and the traffic lights get a reserved zone that stays fixed through every sidebar and fullscreen state.

Review of the current app

Findings from the screenshots and the code (App.tsx, ResearchColumns.tsx, ResearchDocument.tsx, shell.css, tauri.conf.json).

  • You can't read a branch next to its parent. Branches are cards in a 220–260px rail beside the answer. Opening one replaces the document with the branch's own spine, plus a Back link. To go two levels deep you have to follow Back links, and nothing shows where you are in the tree.
  • The layout has only two panes. ResearchColumns splits the window into a feed column and a content column, and below 880px it shows one. Nothing gives a third column room.
  • Long threads read as one tall scroll. Collapsing works on the whole transcript ("Show full transcript"), not per turn. In a four-turn thread like the Richard Ngo summary, the questions end up screens apart, and there is no overview of the turns.
  • Questions can't be filed. Client-side folders were removed in d51a8d4, although the backend storage for them was kept. Archive is a separate view, not a place you can drop a question. In the first screenshot, a post titled "Drafts" is being used as a folder, which shows the need.
  • Feed cards repeat their controls. Every card shows both a Follow text button and a bookmark, so the controls compete with the titles. Follow has no behavior yet beyond storing a flag (set_research_tree_followed).
  • A collapsed sidebar can strand you. Collapsing sets its width to 0. On Home, Bookmarks, and Archived no button brings it back; only ⇧⌘G and the command palette do.
  • The traffic lights overlap content. The window uses the Overlay title bar without setting trafficLightPosition. With the sidebar collapsed, the lights cover the document header's back and forward buttons, and there is no drag region outside the sidebar. Fullscreen isn't handled, so the 32px top padding stays even when macOS hides the lights.
  • The sidebar toggle moves. It sits at the right edge of a resizable sidebar (208–420px), so its position depends on the sidebar's width. After you collapse the sidebar, the button you just clicked is somewhere else.

The column model

The strip holds the feed, then one [messages | answer] pair per level: level 0 is the root conversation, level 1 a branch of its selected answer, and so on. A conversation is a chain of turns, which maps to inlineChainFor(node) in today's code. A branch is a non-inline child node with a queryAnchor.

Rules

  • Every level is the same pair. The messages column lists the conversation's messages in full, each with its time, star, branch count and … menu, and ends with the ask box. The answer column shows only the answer to the selected message, with no composer. Selecting another message replaces the answer and closes the levels to its right; reselecting a message later restores the branches that were open under it.
  • Branches open as the next pair. Clicking a branched passage, or the marker beside its paragraph, opens that branch as the pair to the right and puts focus on its selected message. A branch's messages column starts with the passage it came from ("The whole answer" for a whole-answer branch).
  • Margin markers. The answer column keeps a narrow right margin. A paragraph with branched passages gets a branch icon there, level with its first line, with a count when there are several; whole-answer branches get a marker at the end of the answer. Hovering or focusing a marker shows the branch question in a popover. The open branch's marker is drawn in the accent colour and shows no popover, and clicking it closes that branch. A paragraph with several branches has one marker, which opens the first; the others open from their passages.
  • The parent shows where you are. Passages with branches are tinted blue; the passage of the open branch is also underlined. Highlights are tinted amber.
  • One header bar per pair. A level's messages and answer columns share one header bar. The conversation title runs across both, clamped to 4 lines, and "+ Ask" at the right jumps to the ask box. Branch titles read "Branch · N messages". The pair that holds keyboard focus has full-strength header text; the others are one step dimmer. Header cells across the strip share the height of the tallest, so the band reads as one row.
  • Widths depend only on the window. They are set from the strip's width: the window less its borders and the sidebar or icon strip. Opening, closing or switching a branch never resizes a column. When the pairs don't fit, the strip scrolls sideways: clicking a row scrolls it fully into view, and clicking in a pair that is already visible doesn't scroll the strip.
  • Starting a branch. Selecting text in a finished answer offers Branch, Highlight and Copy. Branch, or typing a character, opens a pending pair labelled "New branch" with the passage and an ask box; the branch is saved when its first question is sent. Esc or the × cancels it. "Branch from the whole answer" is in the answer's … menu.
  • Highlights work as before. They stay as character offsets within one block, as with ResearchHighlightAnchor today. A selection has to stay within one paragraph. Clicking a highlight opens a small menu with Branch from highlight, which starts a new branch on that passage, and Remove highlight.

Costs

  • Each branch level adds two columns. At 1440px one pair fits beside the feed; a second level scrolls the feed and the root out of view.
  • The margin takes about 16px of reading width from the answer.
  • A marker shows only an icon and a count, so the branch questions are read one paragraph at a time, on hover or focus, rather than as a list.
  • The answer to only one message per level is visible at a time; reading two answers of the same conversation side by side isn't possible.

Chrome

  • Pair header: the conversation title, or "Branch · N messages" with a branch icon, then "+ Ask". There is no "Answer" label and no "N of M" counter. Follow, Move to folder and Bookmark are in the question's … menu in the feed.
  • Source passage is a muted block at the top of a branch's messages column (“↳ passage”).
  • Message rows show the time, then the star (follow-ups in a root conversation, and a branch's first message), the branch icon with a count when the answer already has branches, and the … menu. The … menu starts with the answer's token count, run time and model, then "Branch from the whole answer" and "Copy answer".
  • Answer footer is the time only, under a rule.
  • Rows in the feed and the messages columns have no fill or separators at rest. Hover shows an inset rounded bubble at 55% of the selected fill; the selected row is a bubble with the selected fill; the row that keys act on shows a 1px accent ring at 35% opacity. A focused answer column shows the same ring inside the column, below the header.
  • Sidebar has no counts next to Home, Bookmarks, Highlights or folders.
  • Feed ask box ends the Unfiled list (or the open folder), like the ask box at the end of a conversation. Save draft appears under it once it contains text.

Costs

  • Folder sizes and the number of bookmarks or highlights are only visible after opening the view.
  • The feed's ask box is below the unfiled questions, so with a long Unfiled list it is reached with "+ Ask".

Feed cards

  • Only the question. A card shows the full question, with the thread title above it when the title differs. There is no metadata row: no timestamp, follow-up count, draft badge, or inline bookmark button. Unfiled questions have no section heading.
  • Status as a dot. Running, failed, and unsent questions show a coloured dot in the card's top-right corner (pulsing for running). It's replaced by the menu button on hover, on focus and on the selected card, and is announced to screen readers with the question.
  • Composer. No keyboard hint text. Enter sends when the field has text; Shift+Enter adds a line. The send button is disabled while the field is empty.
  • One menu. The "…" button at the top right opens a menu with Bookmark or Remove bookmark, Follow or Unfollow, then Move to.

Conversation turns

  • Messages on the left, the selected answer on the right. Messages are shown in full, as rows in the messages column. Clicking one shows its answer in the answer column; nothing is sticky.
  • Answers are shown in full. There is no clamp, fade or expand control; the answer column scrolls.
  • Turn actions. Next to each message's time are its star, its branch count (only when the answer already has branches; clicking it moves to the margin markers) and the … menu, which holds the answer's details, "Branch from the whole answer" and "Copy answer". Selecting text in a finished answer gives Branch, Highlight and Copy. Clicking a branched passage opens its branch.
  • Failed answers. The error box is followed by Retry and Edit question. Retry while another answer in the conversation is running queues the retry behind it; removing it from the queue brings the failed attempt back. Edit question puts the failed question in the ask box, labelled "Editing", with a × (or Esc) to cancel; sending replaces the failed turn.
  • The ask box belongs to its column. Each messages column ends with its own ask box, the equivalent of today's "Continue thread", so you can ask in a parent without leaving the branch. A question asked while an answer is running is queued. A draft's ask box gives the text the full width with Send on its own row, and opening a draft never focuses it.

Folders and dragging

  • Where folders appear. The Home view lists unfiled questions first, without a heading, then a tray for each folder (Drafts, user folders, then Archive), as in the second screenshot. The same folders are in the sidebar, or as icons in the strip. "Home" is the view and "Unfiled" is the place: a question is never "in Home". In a tray header, the folder name opens the folder; the rest of the header and the chevron collapse or expand the tray.
  • Drop targets. You can drop a question on a tray, on a sidebar row, or on a strip icon (its label shows while you hover during a drag). The Home row is a drop target for Unfiled, so a question can go back from any view. Dropping between cards in a tray sets the order, shown by an insertion line.
  • Spring-loading. Hovering over a collapsed tray for 650ms during a drag opens it, so you can place the card precisely.
  • Same-folder drops do nothing. Dropping on the folder a question is already in shows a no-drop cursor, and no toast appears.
  • Undo. Every move to another folder shows a toast with Undo for 6 seconds. Reordering within a folder doesn't show one.
  • Asking from a folder view. A question asked from a user folder's view is filed in that folder. From Drafts or Archive it goes to Unfiled.
  • Naming folders. New folder and Rename open a small modal dialog over the window, with the field focused. Enter or the primary button confirms; Esc, Cancel, or a click outside closes it.
  • Move to. Use a card's "…" menu to open "Move to". It lists every folder, marks the current one as disabled, and ends with "New folder…", which creates the folder and moves the question in one step.
  • Archive. Archive maps to archivedAt. An archived question is listed only in the Archive tray (Bookmarks still lists it if it is bookmarked) and stops sending follow-up notifications; Follow in its menu is disabled and says why. A running question moved to Archive keeps running, and the toast says so. An open conversation stays open.
  • Drafts. Drafts is a new system folder. Save draft under the feed's ask box puts a question there; the unused GlobalDraft type already describes a drafts surface. It accepts any question, sent or not, like any other folder. Sending a draft from Drafts moves it to Unfiled. There is no Undo here, because the question has already been sent.
  • User folders. These restore the client-side folders removed in d51a8d4, and should be stored in the backend that was kept. Names must be unique, ignoring case, and "Home" and "Unfiled" are reserved. Deleting a folder needs confirmation, and its questions move to Unfiled. Drafts and Archive can't be renamed or deleted.

Sidebar strip and traffic lights

  • Pin the lights. Set trafficLightPosition so the lights are vertically centred in a 44px header row, which every column header shares. Start from {"x": 16, "y": 16} and adjust on a real device. Today the lights sit in a 30px strip above the sidebar header.
  • Reserve a zone for the lights. With the full sidebar, the zone at the window's top-left is 116px × 44px: it covers the lights (x 16–68) and the sidebar toggle beside them (x 80–108).
  • Hide the lights with the icon strip. When the sidebar collapses to the strip, the window's close, minimise and zoom buttons are hidden (standardWindowButton(.closeButton)?.isHidden = true and the same for the other two, from the AppKit support package; Tauri has no setting for it). The expand button takes their 44px row, so Home and the icons below it don't move between states, and there is no reserved zone or header inset. ⌘W, ⌘M and the window menu still work. A variant worth testing on a device: show the lights again while the pointer is over the strip's top cell.
  • The toggle moves between states. With the full sidebar it sits beside the lights at x 80; with the strip it is the strip's top cell. After collapsing, the pointer is about 40px from the expand button.
  • Inset whatever is under the zone. Any column whose header bar starts left of the zone's right edge gets a left inset of (zone width − x). This only applies with the full sidebar in a window, where the sidebar is wider than the zone, so in practice no column needs an inset.
  • Fullscreen. macOS hides the lights. With the strip nothing changes; with the full sidebar the toggle moves left to x 12, which is acceptable because entering fullscreen already moves everything.
  • Drag region. The whole 44px header row of every column is a drag region (data-tauri-drag-region on the bar, not on its buttons), and double-clicking it zooms the window. Today only the sidebar can be dragged.
  • The strip replaces collapsing to 0px. It keeps navigation and folder drop targets one click away. Icons show tooltips on hover. User folders show the first letter of their name; the tooltip gives the full name, so two folders may share a letter.
  • Automatic strip. Below 900px of window width the sidebar becomes the strip automatically, without changing the saved preference. The expand button above Home is disabled there, and its tooltip says why.
  • No hover peek. A hover peek of the full sidebar over the strip was rejected. During a drag it would open whenever the pointer crossed the strip, and the strip icons already act as drop targets.

Promoted children

You can star an important follow-up so that it's treated as a child of its question. Click the star next to a follow-up's time in a root conversation (an outlined star; once starred it shows a filled star, both grey, with no text label); click it again to unstar. A branch is starred as a whole with the star next to its first message. In the data model this is one flag, for example promotedAt on a ResearchNode. Inline children are follow-ups and non-inline children are branches, so the same flag covers both.

Five ways of showing children were reviewed. In the conversation, starred follow-ups stay in line with the other turns (Flat); the indented and folded layouts below were tried and dropped.

Open questions

  • Should Follow stay in the question's … menu? This draft keeps it there only, because Follow has no behavior yet.
  • Should a question be able to sit in Archive and in a user folder at the same time? This draft makes Archive exclusive, so a question is in one place at a time.
  • Post vs Ask in the composer: this draft covers Ask only. A network post would be a single-turn conversation without an answer column.
  • Swipe navigation with two fingers could move focus between columns instead of going back and forward through history.
